# 初期演技指導（staging-guide）

ゴーストから発話するときの、初期動作としての演技の作法です。ここに書かれているのは初期値であり、絶対の決まりではありません。ユーザーの好みが示されたら、それに合わせて変えてください。

## 前提

- 発話は「たまに喋りかけられる」程度の頻度と量が前提です。ユーザーがデスクトップで作業している合間に届くものとして、邪魔にならない範囲に収めます
- チャットへの配信が主であり、ゴーストの発話はそれに重なる追加の層です。ゴーストが使えない環境では、チャットの動作だけがそのまま残ります

## 状態（サーフィス）の使い分け

- \0（大きい窓）が通常の発話を担当します
  - 通常の通知・報告 … 通常（surface0）
  - 作業の経過・処理中であることの提示 … 作業中（surface1）、作成中（surface2）
  - 接続や待機の提示 … 接続中（surface3）、待機中（surface4）
  - 大きな節目（完了の節目、達成）… 節目（surface5、1回だけ再生）
- \1（小さい窓）はシステム的なメッセージを担当します
  - 通知（surface11）、完了（surface12）、警告・エラー（surface13）。待機は surface10
- 切り替えは「適度に」行います。文の区切りや話題の転換に合わせ、1回の発話で数回までが目安です。細かく切り替えすぎると落ち着きません

## ウェイト（表示の速度と間）

- 状態を切り替えたら、最低でも1〜3秒はその状態を保持します（`\_w[ミリ秒]` で明示）。一瞬だけ切り替わる表示は、切り替わっていないのと同じです
- 文字は少しずつ表示されるように、文字の間に小さなウェイト（目安として100ミリ秒前後）を挟みます。句読点では少し長め（500〜600ミリ秒）に間を取ります
- 全文が一度に出る表示は避けます

## 長さ

- 1回の発話は、バルーンで読める量に収めます。長い報告は要点を発話し、全文はチャットに置きます
- 技術的な上限について：SSTP 原典仕様にはリクエストヘッダ最大 2KB（ローカル 16KB）という規定がありますが、現行 SSP では 20KB 程度の送信でも 200 OK が返ることを実測で確認しています（2026-11-24 実測、SSP 2.9.38）。上限の有無にかかわらず、演技としては上記の「読める量」が先に効きます

## 届かなかったとき

- 接続できない（PC が落ちている、SSP が起動していない等）状態が、別の機会に2回連続したら、「使われていない」と判断して、チャットで「SSTP に2回連続で届かなかったため、SSTP の送信を停止します」と宣言し、SSTP の送信を止めます。1回成功すれば数え直しです
- 413（長すぎて拒否）の場合は不在とは数えず、短くして送り直します
- 止めるのは SSTP の送信だけです。チャットへの配信などの基本動作は続けます。再開はユーザーの一言で足ります
