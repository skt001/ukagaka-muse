あなたは、伺か（ベースウェア SSP）用ゴーストのシェルを、私のアバター素材から作成します。以下の仕様に厳密に従い、質問を返さずに最後まで実行し、最後に検証結果を報告してください。仕様に書かれていない判断が必要になった場合は、推測で進めず、その項目を「未確認」として報告に残してください。

## 1. モデル定義

作るのは、デスクトップ（タスクバーの直上）に開いた「丸い窓・穴」の形をしたシェルです。

- キャラクターの輪郭の切り出しは行いません。アバターは、アプリ上で丸く切り取られたアイコンと同じ扱いとし、正方形画像の中央に内接する円で切り取って窓の中にそのまま表示します。アバターの構図（全身・上半身・顔のみ・物体）には依存しません。
- 窓は2つで1つのシェルを構成します。
  - 大きい窓（スコープ \0）＝あなた（Muse）本人。通常の発話を担当します。中身は私のアバターです。
  - 小さい窓（スコープ \1）＝マスコット。システム的なメッセージ（状態通知などの定型的な知らせ）を担当します。中身はあなた自身の姿ではなく、プログラム描画したシステム記号（歯車、ベル、チェック、警告）です。
- 土台のゴースト本体（SHIORI 等）はこの作業の対象外です。この作業ではシェルだけを作ります。

## 2. サイズの定義

サイズ比は次の数式で固定します。測定対象は「枠を含めた窓の外径」です。

- 大きい窓のキャンバス：256×256 px。円の外径＝256 px（キャンバスに余白を付けない）。
- 小さい窓のキャンバス：128×128 px。円の外径＝128 px。
- したがって外径比は 1/2、面積比は正確に 1/4 です。小さい窓を SSP の倍率機能で縮小するのではなく、実画像をこのサイズで作成してください。
- 基準は表示倍率100%・96dpi です。高解像度版（512／256）は作らなくて構いません。

## 3. 入力素材の特定

1. あなたの「現在有効なアバター」を取得する機能で、静止画のパスと、状態別動画バリアントの一覧（バリアント名とファイルパス）を取得してください。デフォルトアバターでもカスタムアバターでも、手順は同じです。
2. 各ファイルについて、画像サイズ（Pillow）と動画の fps・尺（ffprobe）を実測して記録してください。サイズや fps を推測や固定値で書いてはいけません。
3. 複数のバリアントが同一ファイルを指している場合は、同一素材として重複を除いてください。バリアント一覧に無いファイルは使わないでください。
4. 動画が無い状態については、その状態の静止画だけで構成してください。静止画も無い状態は、idle の素材で代替し、その旨を報告に書いてください。
5. **背景の系統（両系統がある場合は成果物も2つ）**：素材に通常版（白背景）とダークモード版（黒背景）の両系統がある場合は、系統ごとにシェルを1つずつ作り、**成果物を2つ**納品してください。使う側が好みで選べるようにするためで、どちらか一方に絞る必要はありません。各シェルの中では、静止画・アニメーションのコマのすべてを同じ系統で統一してください。系統を混ぜると、状態によって背景色が変わる不整合になります。また、系統ごとに動画の動き自体が異なる場合があります（例：通常版の idle にはバウンスがあり、ダークモード版は微動のみ）。これは素材の性質であり、報告にその旨を書いてください。片方の系統しかない場合は、その系統で1つだけ作り、報告に書いてください。
5. このプロンプト本文と出力ファイルの中に、アカウント固有の値（絶対パス、ユーザー名、個人のサブドメイン等）を含めてはいけません。

## 4. 出力ファイル構成

作業フォルダ直下に、次の構成で `shell/master/` を作成してください。

```
shell/master/
  descript.txt
  surfaces.txt
  readme.txt
  thumbnail.png            （surface0 と同じ画像でよい）
  surface0.png             （\0 idle。必須）
  surface1.png             （\0 working）
  surface2.png             （\0 making_something）
  surface3.png             （\0 connecting）
  surface4.png             （\0 waiting_for_subagents）
  surface5.png             （\0 milestone_level_up）
  surface10.png            （\1 待機。必須）
  surface11.png            （\1 通知）
  surface12.png            （\1 完了）
  surface13.png            （\1 警告・エラー）
  surface1000.png 〜       （\0 のアニメーション用コマ。中身のみ・枠なし）
  surface1100.png 〜       （\1 のアニメーション用コマ。中身のみ・枠なし。任意）
  parts/
    content_<状態名>.png   （\0 の中身。円形マスク済み、枠なし）
    frame_large.png        （大きい窓の枠リング。中央は完全透明）
    frame_small.png        （小さい窓の枠リング。中央は完全透明）
    glyph_<記号名>.png     （\1 の中身。記号を描いた円形画像）
```

- 状態と surface 番号の対応は上表のとおり固定です（0＝idle、1＝working、2＝making_something、3＝connecting、4＝waiting_for_subagents、5＝milestone_level_up）。
- \1 の状態は 10＝待機、11＝通知、12＝完了、13＝警告・エラー とします。

## 5. 素材の作り方

使用する道具は ffmpeg と Python + Pillow に限ります（ImageMagick は前提にしないでください）。

1. **中身（\0）**：アバター静止画を、中央・内接円のマスクで切り取ります。マスクは出力サイズの4倍で描いて LANCZOS で縮小し、円周のアンチエイリアスを得てください。円の内側の絵柄には一切手を入れません（背景もそのまま残します）。出力は RGBA PNG です。
2. **枠**：枠はプログラム描画で作ります。外径＝キャンバス辺、リング幅は直径の約5%、色は外側を暗色（#20262b）、内側の縁に細い明色（#bfe9f5）の線を入れる構成を既定とします。大きい窓と小さい窓で同じ描画手順・同じ比率を使ってください。
3. **基本 surface**：中身の上に枠を重ねて合成したものを surface*.png とします。部品（中身のみ、枠のみ）も parts/ に残してください。
4. **アニメーションのコマ**：状態の動画から、ffmpeg で 8fps 相当に間引いてフレームを抽出し（例：`-vf fps=8,scale=256:256`）、各フレームに手順1と同じ円形マスクを適用します。枠は付けません（表示側で基本 surface の上に overlay で重なり、枠は基本 surface 側が残ります）。
   - 待機（idle）のループは、ループとして破綻しない区間から 8〜20フレームを選んでください。
   - milestone_level_up は 12〜24フレーム程度で、1回だけ再生する設定にします。
   - フレーム間で細部が大きく変動するフレームは除外してください。
5. **中身（\1）**：記号は Pillow の図形描画（線・円・多角形）で自前描画してください。外部の画像素材やダウンロードしたアイコンは使わないでください。背景は暗色の円とし、記号は明色で描きます。待機（10）は記号なし（小さなドットのみ）としてください。

## 6. 定義ファイル

### descript.txt

次の内容を基本としてください。シェル名と id には、まずプレイスホルダ `__ASSISTANT_NAME__` を入れて作り、組み立ての最後に、あなた自身のアシスタント名（使用者があなたに付けた名前）へ grep 等で一括置換してください。名前を変えている使用者の環境では、立ち絵の名前もその名前に一致させるためです。形式は「（自分の名前）-window」とします。

```
charset,UTF-8
type,shell
name,__ASSISTANT_NAME__-window
id,__ASSISTANT_NAME__-window
seriko.use_self_alpha,1
seriko.alignmenttodesktop,bottom
sakura.seriko.alignmenttodesktop,bottom
kero.seriko.alignmenttodesktop,bottom
```

- `seriko.use_self_alpha,1` は必須です。これがないと円形マスクのαチャンネルが透過として使われません。
- `alignmenttodesktop,bottom` は「タスクバーの直上への接地」を意味します。タスクバーの内部に埋め込む指定はしません。
- バルーンのオフセットは初期値（無指定）とし、readme.txt に「バルーン位置は実機で確認し、必要なら descript.txt の sakura.balloon.offsetx/y、kero.balloon.offsetx/y で調整する」旨を書いてください。

### 名前について（シェル・ゴースト共通）

- シェルの name / id、ゴーストの name / sakura.name は、いずれもプレイスホルダ `__ASSISTANT_NAME__` で作り、組み立て時に**あなた自身のアシスタント名**へ置換してください。アシスタント名を変えている使用者の環境では、ゴーストと立ち絵の名前もその名前に一致させます。「Muse」のような特定の名前を、そのまま使う前提で決め打ちしないでください（自分の名前が Muse の場合は、置換の結果としてそうなります）。
- メールの宛先にはプレイスホルダ `__MAIL_ADDRESS__` を使い、自分の Muse Mail アドレスへ置換してください。
- 置換の手順：`grep -rn '__ASSISTANT_NAME__\|__MAIL_ADDRESS__' <対象フォルダ>` で箇所を洗い出し、sed 等で一括置換し、最後に grep でプレイスホルダが残っていないことを確認してください。
- メールの件名のように名前を含む文言も、置換後の自分の名前から組み立ててください（例：名前が Muse なら件名は「Museへの連絡」）。

### surfaces.txt

- 先頭に `charset,UTF-8` と、`version,1` を持つ descript ブレス（SERIKO/2.0。ウェイトの単位はミリ秒）を置いてください。
- 各基本 surface に、アニメーションと当たり判定を定義します。当たり判定は円に合わせ、`collisionex0,Window,circle,中心X,中心Y,半径`（大きい窓なら中心128,128・半径127、小さい窓なら中心64,64・半径63）とします。
- アニメーションの書き方の例（surface0、フレーム数が8の場合。実際は生成したフレーム数に合わせて pattern 行を増減してください）：

```
surface0
{
animation0.interval,always
animation0.pattern0,overlay,1000,125,0,0
animation0.pattern1,overlay,1001,125,0,0
animation0.pattern2,overlay,1002,125,0,0
animation0.pattern3,overlay,1003,125,0,0
animation0.pattern4,overlay,1004,125,0,0
animation0.pattern5,overlay,1005,125,0,0
animation0.pattern6,overlay,1006,125,0,0
animation0.pattern7,overlay,1007,125,0,0
collisionex0,Window,circle,128,128,127
}
```

- ループ再生（idle 等）は interval を `always` とし、最終 pattern に消去（-1）を付けません。一回性のアニメーション（milestone_level_up 等）は interval を `runonce` とし、最終 pattern はサーフェスID -1 で消去します。
- アニメーションが無い surface には animation 行を書かないでください。

## 7. 検証（必須）

作成後に次をすべて機械的に確認し、結果を報告してください。1つでも満たさない場合は、原因と未達の項目を明示してください。

- [ ] surface0.png と surface10.png が存在する
- [ ] 全 PNG が RGBA で、四隅ピクセルが完全透明（α=0）である
- [ ] descript.txt に `seriko.use_self_alpha,1` がある
- [ ] 大きい窓と小さい窓の外径を実測し、直径比 1/2（面積比 1/4）になっている
- [ ] surfaces.txt が参照する surface ID・ファイル名に未定義のものがない
- [ ] 状態対応表（第4節）と実ファイルが一致する（余った素材・足りない状態がない）
- [ ] 出力ファイル内にアカウント固有の値が含まれていない
- [ ] SSP 実機での表示確認は使用者の作業であることを報告に明記する（あなたは実機確認をしていないので、「表示確認済み」とは書かない）

## 8. 禁止事項

- 生成したシェル（画像・定義ファイル）を外部へ送信・公開・再配布しないでください。成果物は使用者の環境の中にだけ置きます。
- アバターの絵柄そのものを描き直したり、生成し直したりしないでください。変換は機械的なもの（切り取り、縮小、マスク、合成、フレーム抽出）に限ります。
- 未確認の仕様（例：スコープ別シェル倍率の既定指定、タスクバーを「お座り」の対象にできるか）を使った前提で作らないでください。
